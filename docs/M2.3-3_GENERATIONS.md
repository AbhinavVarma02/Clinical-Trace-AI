## Construction and trust boundary

The existing `create_mock_beta_app` factory accepts an explicit `generation_root` beside its control catalog. Omitting it retains the M2.3-2 acquisition-only configuration. The root contains private `staging`, `objects` and `state` directories. Only catalog-published opaque generation IDs resolve through the API. A catalog stores a hash of its configured root, so pointing an existing catalog at another root fails startup.

The existing signed MOCK OIDC, state/nonce/PKCE, revocable session, strict Origin/CSRF, header rejection, quotas and transport policy remain in force. The live allowlist is empty. All construction requires in-process MOCK transports. Clinical routes resolve the owner and exact patient before accessing a generation. Source and patient identity come from backend policy. The existing question guard also checks the other invented patient alias and IDs.

| Owner-authorized endpoint | Behavior |
|---|---|
| `GET /beta/epic/patients/{alias}/status` | Last attempt, active generation, last successful generation, epoch and serving state |
| `POST /beta/epic/patients/{alias}/refresh` | Existing bounded, idempotent admission and background acquisition |
| `POST .../generations/{gid}/select` | Validate and explicitly select the named generation |
| `POST .../generations/{gid}/rollback` | Verify target and publish it under a new epoch, with a sign-in less than five minutes old |
| `POST .../generations/{gid}/runs` | JSON containing only a question, bounded to 1,000 characters and 4 KiB of request bytes |
| `GET .../generations/{gid}/runs/{id}` | Resolve the original persisted run within its original generation |
| `POST .../generations/{gid}/runs/{id}/review` | Apply the current clinical-use boundary, then submit the original answered run to the existing review service |
| `GET .../generations/{gid}/reviews/{id}` | Resolve the original review and hash-bound evidence |
| `POST .../generations/{gid}/reviews/{id}/decide` | Reject owner self-approval because an independent authenticated reviewer is unavailable |

Mutations require the existing session-bound CSRF token and exact Origin. Cached, stale and rolled-back clinical use additionally requires `X-Beta-Cache-Ack: 1` on each request naming the exact generation. All clinical responses use `Cache-Control: no-store`.

Every review-submission POST rechecks that boundary, including an idempotent request for an already submitted run. Fresh generations permit authorized submission. Cached, stale or rolled-back generations within seven days require acknowledgement on that request for its exact generation; a previous selection or submission does not carry acknowledgement forward. Beyond seven days, new submissions return `generation_expired`, even with acknowledgement. Historical GET access remains subject to the separate 30-day policy and original artifact integrity checks. Original generation pins, run contents and review hashes are unchanged.

## Mapping and coverage

The acquisition retains approved resources only in memory. It strips DocumentReference bodies, inline attachments, URLs and narrative before staging. Metadata and its original content hash remain separately recorded in the immutable manifest. No DocumentReference note body enters the clinical store.

The M1 `EpicMapper`, FHIR validator, reference rewriting, provenance and content hashing normalize approved clinical resources. Every generation contains exactly one allowlisted patient. Clinical dates retain the source field's meaning and precision. Retrieval time appears in provenance and acquisition metadata. The existing mapper labels a substituted record `meta.lastUpdated` as metadata only.

The initial profile is the exact Patient read and seven searches. MedicationRequest and Binary remain excluded. Mapping rejects every unexplained clinical rejection. The sole enumerated import exclusion is DocumentReference clinical-note bodies. Unsupported fields handled by M1 remain explicitly recorded in its field-status report. The MOCK boundary rejects conflicting identities, reversed encounter periods, invalid status values, cross-patient references, unexpected DiagnosticReport result types and instruction-like content identified by the existing guard.

Per-operation coverage records execution, import state, pages, observed matches, unique identities, duplicates, mapped records, exclusions and rejections. A terminal successful empty search is `returned_none`. A nonempty search with mapping loss becomes `partially_imported` or `not_imported` and blocks publication. Failed or truncated execution never becomes a complete empty result. Metadata-only notes report `not_imported` with a policy reason. Unresolved local references remain a separate count and preserve the existing clinical disclosure or abstention behavior.

The clinical runtime explicitly carries note-body exclusion and separate document/discharge-summary metadata coverage from the validated manifest, including when reopening an existing generation. Returned discharge-summary metadata establishes that the document metadata was found; its excluded body cannot be reviewed. A completed search returning no matching metadata describes the search result and does not confirm documentation absence at the source. Neither case becomes a high-severity missing-discharge-summary finding or an Encounter/Patient citation claiming that the document does not exist. Completeness tools and answers disclose these limits without treating coverage as clinical evidence. Fully imported synthetic fixtures retain their existing documentation checks, and supported encounter-data gaps remain reportable.

## Publication and evidence pins

Admission captures the patient's publication epoch and authorization revision in the control catalog. Every outbound operation still checks the session and patient. Publication rechecks that the attempt is running and its captured epoch/revision still match.

1. Normalize into a private staging directory. Write and fsync the canonical bundle and manifest.
2. Build a separate deterministic clinical runtime from those exact bytes, validate its stored resources and smoke-test its index. Close and flush its SQLite state.
3. Verify the files again and rename the immutable directory on the same volume.
4. Recheck finalized files, runtime resources, authorization, epoch and deadline. In a single SQLite transaction register the generation, update the pointer and epoch, and record successful attempt status and publication audit.

A failed candidate leaves the previous pointer intact. Finalized orphan files have no catalog authority and cannot be selected. A successful pointer commit remains a success if the process stops immediately afterward. Rollback uses the same integrity and authorization boundary and increments the epoch, fencing older acquisition work. It preserves the last successfully retrieved generation and the target's original retrieval and promotion times.

Each generation has a separate persistent clinical SQLite database using the existing runtime, retrieval, agent, audit and review components. A run is pinned before execution. Refresh does not replace its runtime. Run results, individual evidence items and review artifacts carry the source, patient, generation, bundle hash, manifest hash, mapping version, policy and original retrieval time. Existing resource versions and upstream lineage accompany evidence. Review artifact hashing includes that context. Catalog pins also validate persisted run/review content hashes after restart. Missing or altered evidence fails explicitly. A citation never resolves through the current active pointer.

LLM inference, external tracing and the Epic readmission model remain disabled. The owner can create pending review artifacts. An independent reviewer identity and its authority remain a later decision.

## Cache, retention and local recovery limits

The provisional defaults are 24 hours fresh, seven days of explicitly acknowledged continued clinical use and 30 days of historical run/review access from artifact creation. Any newer admitted refresh makes retained evidence cached while pending or after failure. Older evidence becomes stale after the freshness window. Rollback is labelled `rolled_back`. Expired or integrity-failed evidence is unavailable for new clinical use. Historical artifacts retain their original generation until their separate access window expires.

The provisional storage budget is 256 MiB with reserved staging headroom and a 20 MiB normalized-candidate ceiling. A full store rejects new admission before acquisition, while duplicate idempotent requests retain their existing attempt. Orphan staging and finalized directories remain quarantined and count toward storage. Automatic erasure and hosted retention remain owner decisions.

Tests force process termination during staging, before finalization, after finalization, before pointer publication and after pointer commit. Restart preserves a complete pointer, interrupts abandoned attempts without replay and reopens historical run/review state. Additional tests inject ENOSPC/write errors, revocation, rollback races, file and state tampering, in-flight refresh and missing evidence.

Files are fsynced, and SQLite publication uses synchronous FULL. This Windows environment does not provide portable directory fsync. The local process-interruption results establish the demonstrated recovery behavior. Power-loss durability, hosted filesystem semantics, actual ACL/volume protection, encryption, backup/restore and multi-host operation remain separate gates. Where Windows disallows creating an actual symlink, the test exercises the same reparse-point rejection using injected lstat metadata. The service supports one exclusively locked control-catalog worker.
