## Request and trust boundaries

Use the existing FastAPI app in one isolated Beta instance with a single refresh worker and a durable SQLite control catalog. A Beta-only `POST /beta/epic/patients/{alias}/refresh` takes an idempotency key and returns `202` with an opaque attempt ID. `GET /beta/epic/patients/{alias}/status` reads the catalog with the same owner and patient checks. Rollback is a separately authorized `POST` targeting a retained generation. A repeated submission with the same key and request returns the existing attempt. Reusing a key with a different request yields `409`. A different request during a refresh gets `409`, and exhausted quotas get `429` with a retry time. Persist idempotency and quota accounting across restarts. A browser disconnect leaves the admitted attempt bounded by the same deadline. A server restart terminates the unfinished attempt without replay.

The backend validates owner identity through an approved MFA-protected OIDC account using authorization code + PKCE, `state` and `nonce`, verified signature/issuer/audience/expiry and an exact `(issuer, subject)` binding. Use a revocable server-side session with a rotated opaque `Secure`, `HttpOnly`, host-only `SameSite=Lax` cookie, strict same-origin checks and CSRF tokens on mutations. Recheck owner/session and patient policy at admission, before outbound calls and at promotion. Gate the entire Beta API at the origin, including status, lists, documents, provenance, evidence, runs, reviews, operations and legacy FHIR routes. Disable alternate paths that cannot honor the same checks. Send `Cache-Control: no-store` on authenticated data responses and disable shared edge caching. Resolve demo roles on the server within the authenticated scope. Retain independent review and prohibit self-approval. If a verified independent reviewer is unavailable, Epic artifacts stay in their existing review-required state.

The allowlist starts empty. It maps opaque app aliases to exact owner-approved official synthetic IDs, the pinned sandbox, a versioned operation policy and revocation state. Store the mapping on the backend outside the repo and build. Reject unapproved aliases, mode overrides and arbitrary IDs, URLs, headers, FHIR operations or scopes before a token request. `X-Demo-Persona`, `X-Demo-Workspace`, `X-Data-Source`, gateway headers and Epic bearer tokens carry no owner authority. Resolve the source server-side and reauthorize every read against its patient and source. Derive namespaces from `(source, patient alias, generation)` for resources, indexes, caches, sessions, runs, reviews and citations. A denied lookup by an authenticated owner returns the same response as an unknown target. Revocation removes current and historical access for that patient and fences active attempts.

## Coverage and serving contract

Record attempt states `queued`, `running`, `succeeded`, `failed` or `interrupted`, with ID, policy version, start/end and stable error code. Per operation record execution (`not_requested`, `succeeded`, `failed`, `truncated`, `unknown` for legacy) separately from import outcome (`imported`, `partially_imported`, `not_imported`, `returned_none`). Include categories, pages, observed matches, unique returned, imported, rejected, excluded, duplicates and unresolved-reference counts/reasons where known. Partial observed counts are lower bounds. `returned_none` requires terminal successful pagination with zero matches and no outcome that makes the result incomplete. Zero mapped resources alone can mean `not_imported`. Unresolved references are a separate local evidence-availability state, with source/version citations where supported.

Require the exact Patient and every requested search to complete. Abort on unknown or error/fatal OperationOutcome affecting completeness, unexpected type/subject/reference, conflicting duplicate identities or versions, invalid required records, unclassified mapper rejection, truncation or exceeded budgets. Identical duplicates can be counted and deduplicated. The technical default permits only approved, enumerated exclusions and reports dangling references to unavailable results. The exact mapping exclusions and thresholds need owner approval. A nonempty required clinical-data search category with zero usable results due to rejection blocks promotion. A truly empty required search can pass with coverage. The DocumentReference search is metadata-only under this profile. Successful metadata retrieval with bodies excluded by policy does not count as a mapping rejection or establish note availability. Every excluded clinical datum stays unavailable. Keep clinical dates, Epic metadata times and retrieval times separate. Preserve the current verifier and abstention behavior when imported evidence cannot support a claim.

Status carries source, `LIVE`/`MOCK`, selected and active generation IDs, mapping/manifest/policy versions, acquisition window, retrieval timestamp, promotion timestamp, last attempt and last successfully promoted retrieval. An answer and its citations carry the actual selected generation, internal resource version, upstream reference/version/hash where available and the relevant coverage. Serving status is `unavailable`, `fresh`, `cached`, `stale` or `rolled_back`, separately from attempt state. `fresh` requires a promoted successful retrieval within the freshness window with no newer admitted attempt. When refresh is pending or fails, retained evidence is offered only through explicit selection of its generation with cache acknowledgement. The owner sees the original retrieval time, age, reason and last attempt outcome. A stale or rolled-back generation carries the same acknowledgement and age restrictions. At the continued-use limit, block new clinical runs. Existing historical artifacts remain bound to their evidence until their approved retention expires. An unavailable source has no automatic substitution. Equivalent content retrieved anew can have a new acquisition time while retaining the same upstream versions.

## Promotion and recovery

1. In one short catalog transaction admit the attempt, charge budgets and capture the patient's publication epoch and allowlist revision. Fetch into a restricted staging directory on the final volume. Store normalized evidence and sanitized provenance/coverage. Discard transient raw responses after mapping. Reuse the mapper and runtime builder with a new staging boundary.
2. Verify schema, patient/source identity, completeness, counts, manifest and bundle hashes. Build and smoke-check the isolated evidence index/runtime from those exact bytes. Persist per-generation agent and review state separately from immutable evidence. Finalize the candidate under a unique private generation path and durably flush the immutable files and rename on the same volume before publishing a pointer. Nothing in staging or an unreferenced candidate is addressable through the API.
3. In one SQLite transaction compare the expected epoch and authorization revision, check the lease/deadline and publish the generation, success timestamps and promotion audit. The pointer is the only serving authority. Use a monotonically increasing publication epoch even when rolling back. In-flight requests, retries, resumed runs and reviews resolve their original pinned generation. Never resolve an old citation against the current active runtime. Keep old runtimes alive for their pins and reopen the matching persistent state after restart. Preserve historical generation metadata in the review artifact hash and verify it before decisions.
4. On restart, verify the published manifest and bundle, rebuild the matching index if needed and restore the corresponding run/review state. Mark abandoned attempts interrupted, fence late completions and clean orphan staging only after checking catalog references. If published evidence or required state fails integrity, mark the source unavailable until recovery. An explicit owner rollback checks the target's integrity, authorization and evidence age, swaps the pointer with the same epoch check and audits the change. Preserve last successful retrieval independently of the rollback target's timestamp. Exercise process kills before finalization, after finalization but before commit, and immediately after commit. Recovery yields the old complete generation or the new complete generation.

- **ISSUE-7** remains a release dependency. The synthetic Patient-cited medication absence claim requires an explicit owner decision, separately scoped correction and verified resolution before release. Existing clinical answers and goldens are outside M2.3-1.
- **A1 medication clinical-date provenance** gates MedicationRequest import and Beta release. Actual pagination, available OAuth grants, shared-sandbox capacity and JWKS propagation require later approved evidence. Zero matched resources is scoped to the queries and time window. The initial profile excludes note bodies, and M1 mapping exclusions can leave evidence incomplete.
- Verify filesystem/SQLite durability on the selected host, volume capacity, restoration and session revocation before any deployment. Keep hosted CI's `ho-013` miss and development dependency install warnings visible in release review. M2.2-f CI establishes its existing gate only. [Project status](PROJECT_STATUS.md).
